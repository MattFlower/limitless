# Limitless — Milestones

Each milestone ends with a demo (a short published page with architecture, screenshots and a live
run) before work continues. Self-hosting starts at M2: from then on, features are built *by the
factory* via PRs against `MattFlower/limitless`, reviewed and merged by the orchestrator.

| # | Milestone | Scope | Demo |
|---|---|---|---|
| M0 | Foundations | Research, architecture, repo scaffold, lint/typecheck/test, CI | Architecture page |
| M1 | Walking skeleton | Daemon + SQLite + pipeline (prepare → triage → implement → gates → audit → cross-vendor review → deliver), claude & codex harnesses, CLI, minimal live UI, PRs to `limitless-sandbox` | A real task → reviewed PR, watched live in the UI |
| M2 | Self-hosting + quality | launchd release deploy; factory builds its own features: spec + blind holdout + verify, fix rounds + tier escalation, quota-aware routing & fallback, gate auto-detection | Factory-built PRs to itself, quality gates catching real problems |
| M3 | Triggers | GitHub webhooks through a Cloudflare tunnel, Discord bot, UI chat concierge, MCP server + skills for Claude Code & Codex | Kick off runs from Discord, GitHub, and a Claude Code session |
| M4 | Cheap & local models | mtplx + twilight llama.cpp + OpenRouter backends; a factory eval suite to calibrate routing; cost dashboards & budget alerts | Dependabot PR handled end-to-end for $0 on local models; routing table justified by eval data |
| M4.5 | Review quality | Research-first redesign of the review stage: a review eval built from real escaped defects and clean controls, graded on what production would block; coverage-first finders from different vendors, a grounded cross-vendor verifier with a consequence-based severity rubric, and a tightening round schedule on verified findings (#109) | Review eval v2 results: the new review system against the old single reviewer on escaped defects, false blocks and cost |
| M4.6 | Spec quality | Research-first redesign of the spec stage (#193): spec depth by implementer tier (none / light / full × Opus / Sol / Luna), acceptance criteria sized to the task, scope kept within the request with conflicts flagged and large tasks split (#137), a decision ledger (#175), measured on a difficulty-stratified implement dataset (#111) | Rounds-to-converge, scope overrun and escaped defects by spec depth and implementer, with the chosen defaults |
| M5 | Hardening & safety | Failure injection (#70), overload control (#150), retention; isolation for code the factory did not write: hardened factory git calls (#60; part 1 landed in #255), an audit that blocks new gitlinks and diff-hiding attributes (#234), factory-owned clones for local repositories (#232), sandboxed edit-mode agents (#233); remote UI through the LAN proxy (#61, landed; replaces Cloudflare Access); optional twilight hosting | Failure-injection and sandbox walkthrough: an agent that tries to write outside its worktree or hide a change from the audit is stopped |
| M5.5 | Agent surface | A surface an agent new to Limitless can use: one concept (a work item: request → PR → review → landed) and five verbs (submit, inbox/ack, answer, review, status) over MCP, CLI and HTTP. A durable event log fed by conditional GitHub polling (no webhook required) and the daemon's own events, with an inbox cursor so a client catches up after any gap; review rounds on the same PR; a landing queue on the reviewed commit that keeps open PRs mergeable (#46); CI rerun, fix and conflict rounds once edit mode is sandboxed; a session-start digest; complete user docs (#71) | The new-agent test: a fresh session with only the MCP server takes realistic tasks to landed PRs, measured by tool calls, errors and human interventions |
| M6 | Portable & work-ready | Providers, models and policy defined in config (no machine-specific catalog); one idempotent `limitless init` that runs the `limitless doctor` checks, detects providers, writes config, starts the service, runs the live smoke checks and offers MCP registration; quota-unlimited providers as a normal state; model-origin constraints (e.g. no China-origin models) enforced by the router; per-repo discreet mode (no factory marks in branch names, commits, PRs or comments; factory PRs tracked by the factory's own records) and merges gated on another reviewer's approval; per-repo gates and review lenses; provider workload analytics; Homebrew tap that builds a self-contained binary, plus a curl installer (#38) | Fresh `brew install` and `limitless init` on a second machine with a different provider set, routed by evals; then a pilot on an unrelated repository |
| M7 | Stage craft | State-of-the-art prompting and technique per stage and per model tier, A/B tested on the role evals (#110); implement eval v2 moved to M4.6 (#111) | Per-stage prompt variants justified by eval deltas |

## Definition of done (from PROMPT.md)
1. The factory has completed tasks end-to-end without errors (tracked in the UI's run history).
2. All eight "Required Functionality" items are shipped and documented.
