1. SUBSCRIPTION USAGE & TOS
===========================================================

Timeline of Anthropic's 2026 policy churn:
- April 4, 2026: Anthropic banned Claude subscriptions from powering third-party autonomous-agent harnesses (e.g., OpenClaw), citing capacity/service abuse — users were burning "hundreds, even thousands of dollars" of tokens on $20–$200 subscriptions. (VentureBeat, https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch)
- May 13–14, 2026: Reinstated third-party/Agent SDK usage, but announced that effective June 15, 2026, Claude Agent SDK, `claude -p`, GitHub Actions, and third-party-app usage would move OFF the subscription rate-limit pool onto a separate, non-rollover monthly credit metered at API list rates ($20 credit for Pro, $100 for Max 5x, $200 for Max 20x). (Gist writeup, https://gist.github.com/MagnaCapax/d9177e35b355853f03c730dfcaa693ef; VentureBeat, same URL as above)
- June 15, 2026 (the day it was to take effect): Anthropic paused the change after sustained public backlash (Jeremy Howard called it "misleading," a wave of public defections to OpenAI/DeepSeek, Anthropic's own social posts got Community-Noted). (The New Stack, https://thenewstack.io/anthropic-pauses-claude-agent-sdk-subscription-change/; AgentConn, https://agentconn.com/blog/anthropic-agent-sdk-credit-walkback-claude-p-saved-2026/)
- Current state (per Anthropic's own Help Center, fetched directly): "Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits" — i.e., the pre-April status quo, with no separate credit pool. (https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

Is it actually *allowed* to drive Claude Max via the Agent SDK / a custom harness? The current legal text (fetched directly from https://code.claude.com/docs/en/legal-and-compliance, Anthropic's canonical page, undated but live as of today) draws a sharper line than the "it's fine again" narrative suggests:
- "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
- "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication... Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users."
- It explicitly protects "an end user [signing] in to the unmodified Claude Code binary with their own Claude subscription."

Net read for a personal, single-user "software factory": running the actual `claude` CLI binary headlessly (`claude -p ...`) under your own OAuth login is squarely inside "ordinary use of Claude Code" and is fine. Building a *custom harness on top of the Agent SDK library* that itself authenticates via OAuth is what the legal page tells you to do with an API key instead — that boundary was never actually reversed; only the "put SDK usage on a separate credit meter" *billing* mechanism was reversed. For your architecture: prefer shelling out to `claude -p` (the CLI) over embedding the Agent SDK with OAuth; reserve the Agent SDK for API-key auth if you need SDK-level control. Anthropic states it "reserves the right to take measures to enforce these restrictions... without prior notice," so there is real (if currently low-probability) enforcement risk either way — this is a gray area, not a green light.

Usage limits mechanics: every paid plan meters two windows — a 5-hour rolling session limit and a weekly limit (Max plans get two weekly caps: one all-models, one Sonnet-specific). Anthropic does not publish absolute token/message numbers, only relative multipliers (Max 5x ≈ 5x Pro's per-session room); the only authoritative readout is Settings → Usage in the Claude Code app / `/usage`. On May 6, 2026, Anthropic doubled the 5-hour limits for Pro/Max/Team/seat-Enterprise. (TrueFoundry, https://www.truefoundry.com/blog/claude-code-limits-explained, and Morph, https://www.morphllm.com/claude-code-usage-limits) Community-measured (unverified) ranges: Pro ≈ 10–45 prompts/5hr, ≈ 40–80 Sonnet-hours/week; Max 5x ≈ 50–225 prompts/5hr, ≈ 140–240 Sonnet-hrs + 15–35 Opus-hrs/week.

ChatGPT side: since April 9, 2026, "ChatGPT Pro" split into **Pro Codex ($100/mo)** — elevated Codex limits, no unlimited Sora — and **Pro Max ($200/mo)** — Codex + unlimited Sora + Operator + advanced voice (matches your stated "$100 plan"). (aipricing.guru, https://www.aipricing.guru/chatgpt-subscription-pricing/) Codex meters on a 5-hour rolling window plus a weekly cap; OpenAI switched to token-based metering in April 2026 rather than fixed message counts, briefly removed the 5-hour cap for Plus/Pro/Business (July 12–30, 2026), then restored it. OpenAI's own published ranges: Plus ≈10–100 GPT-5.6 messages/5hr, Pro-5x ≈50–500, Pro-20x ≈200–2000. (zenn.dev, https://zenn.dev/is0383kk/articles/ac9e6895727fb0; extraheadroom.com, https://extraheadroom.com/codex-usage-limits)

Programmatic usage/rate-limit detection:
- **Claude**: `claude -p ... --output-format stream-json --verbose` emits a `rate_limit_event` with `{type, rate_limit_info: {status, resetsAt, rateLimitType: "five_hour"|"weekly", overageStatus, overageResetsAt, isUsingOverage}}` — status-level only, **no percentage-utilization field**. A feature request to add `used_percent` or a `claude usage --json` subcommand (GitHub issue #78476, https://github.com/anthropics/claude-code/issues/78476) was **closed as not planned**; percentages remain interactive-only via `/usage`, which hits the authenticated `/api/oauth/usage` endpoint that third-party tools can't safely call. Error-reference page (https://code.claude.com/docs/en/errors, fetched directly) documents only user-facing strings, not stable JSON error codes: "You've hit your session limit," "...weekly limit," "...Opus limit," "...Sonnet limit," HTTP 429 "Request rejected," HTTP 529 "Repeated Overloaded errors." A GitHub feature request for automatic fallback from OAuth to `ANTHROPIC_API_KEY` on limit-exhaustion (issue #43260, https://github.com/anthropics/claude-code/issues/43260) is open/unimplemented — you must build this yourself.
- **Community tool `ccusage`** (https://github.com/ccusage/ccusage, https://ccusage.com/): parses local JSONL session logs entirely offline (no API key, no network call) into daily/weekly/per-session/5-hour-block cost & token reports across Claude Code, Codex, and ~15 other agent CLIs — the most practical way to build a pre-flight "how much headroom do I have" check.
- **Codex**: `/status` shows live 5-hour + weekly percentages; JSONL session files under `~/.codex/sessions/YYYY/MM/DD/` record `used_percent`, `limit_5h`, `limit_weekly`, and reset times per turn — notably more machine-readable than Claude's headless output (per commentary inside GitHub issue #78476 itself, which cites Codex's model as the thing Claude Code is missing).

2. OPENROUTER
===========================================================

Docs consulted: https://openrouter.ai/docs/features/provider-routing, https://openrouter.ai/docs/features/prompt-caching, https://openrouter.ai/docs/guides/routing/routers/auto-router, https://openrouter.ai/collections/programming, https://openrouter.ai/docs/faq.

**Provider routing / fallback**: default behavior is price-weighted load balancing — providers with outages in the last 30s are excluded, remaining providers are weighted by inverse-square of price (a $1/M provider is ~9x more likely to be picked over a $3/M one), and failed requests fall through to the next stable provider automatically. You can pin an `order: ["anthropic","openai"]` list, set `allow_fallbacks: false` to hard-restrict to your listed providers, or `sort: "throughput"|"latency"|"price"` to override load balancing. A `models` array lets a single request fall back across *different models/families* (not just providers), and `model:nitro` / `model:floor` are shortcuts for highest-throughput and lowest-price routing respectively.

**Auto router** (`openrouter/auto`, docs: https://openrouter.ai/docs/guides/routing/routers/auto-router): a market-based router driven by aggregate anonymized spend across OpenRouter's user base over a trailing 7-day window per task type — "like a market index." A `cost_tier` param (`low|medium|high|xhigh|max`, default `low`) controls how much you're willing to pay; you're billed at the selected model's normal rate with no extra fee. `openrouter/auto-beta` is the early-access variant.

**Prompt caching** (https://openrouter.ai/docs/features/prompt-caching): automatic/no-config for OpenAI GPT-5.6+, DeepSeek, Grok, Moonshot, Groq, Z.AI, and Gemini (implicit); Claude and Qwen require explicit `cache_control: {"type":"ephemeral"}` blocks. Cache-read discounts: ~0.1x list price for Anthropic/DeepSeek/Qwen, ~0.25–0.5x for OpenAI/Gemini; cache writes run 1x (DeepSeek) to 2x (Anthropic 1-hour TTL) of base price. OpenRouter does "provider sticky routing" to keep repeat requests on the same backing provider so caches actually hit.

**Usage/cost API**: the generation endpoint returns exact post-hoc `total_cost`, `tokens_prompt`, `tokens_completion`; there's a pre-request `estimate_cost()`; `/api/v1/auth/key` gives a live credit-balance snapshot (`credits_used`, `credit_limit`, `remaining`, `is_free_tier`); `/api/v1/usage` tracks BYOK usage against a $25,000/month allowance. Platform fee is 5.5% on credit purchases (min $0.80), not per-inference-call. (truefoundry.com/blog/openrouter-pricing; omidsaffari.com/blog/openrouter-pricing)

3. ROUTING RESEARCH & BENCHMARKS
===========================================================

- **RouteLLM** (UC Berkeley, ICLR 2025, https://github.com/Not-Diamond/awesome-ai-model-routing indexes it): trained a preference-based router that sent only ~14% of MT-Bench queries to the strong model while retaining 95% of GPT-4-level quality, an 85%+ cost cut.
- **FrugalGPT** (Stanford, 2023): cascade routing — try cheapest model, escalate on a learned confidence/verifier signal — demonstrated up to 98% cost reduction on some workloads.
- **NotDiamond**: hosted router that optimizes per-customer using their own traffic/labels. **Martian**: adaptive router that learns online from traffic patterns. **OpenRouter Auto**: market-index based (see §2). All three are compared in https://dreaming.press/posts/2026-06-21-routellm-vs-notdiamond-vs-martian.html and https://www.bestaiweb.ai/openrouter-martian-and-not-diamond-the-2026-llm-router-race-and-where-agent-cost-optimization-is-heading/.
- A 2026 arXiv survey on dynamic routing/cascading frames the design space along three axes: *when* the decision is made (pre-request, mid-inference, or post-first-response), *what* signal feeds it (query features, model metadata, historical performance), and *how* it's computed (static rules, a trained classifier, RL, or a cascade with escalation). This maps directly onto a practical "software factory" heuristic: classify a coding task pre-request using cheap static signals (estimated diff size/files touched, keyword match against "bump/changelog/lint" vs "refactor/design/migrate," which repo paths are touched, whether tests already exist) feeding a small/cheap LLM or rules-based classifier, then dispatch — reserving a FrugalGPT-style escalation cascade (cheap model attempts → verifier/tests fail → escalate to next tier) for ambiguous cases.

These are the right tier to wire in as the "medium difficulty, cost-sensitive" fallback rather than routing everything non-trivial straight to Opus.

4. FALLBACK / RESILIENCE PATTERNS
===========================================================

- **Circuit breakers**: LiteLLM's router (https://docs.litellm.ai/docs/routing) implements this natively — tracks `failure_count`/`cooldown_time` per deployment, marks a model "unhealthy" and skips it for a cooldown window rather than hammering it, with configurable `max_failures` and `circuit_breaker_duration`. OpenRouter does the equivalent at the provider layer automatically (excludes providers with "significant outages in the last 30 seconds" before weighting the rest by price).
- **Retry with backoff**: standard practice is exponential backoff + jitter on 429/500/502/503/504, honoring any `Retry-After` header, with a small retry budget per tier before escalating to the next fallback rather than looping indefinitely on one provider.
- **Provider health checks**: maintain a rolling success-rate/latency window per provider and pull it out of rotation on breach — this is what OpenRouter's price-weighted routing and LiteLLM's cooldown system both do; you'd replicate it locally if orchestrating Claude/Codex/OpenRouter yourself rather than routing everything through one broker.
- **Subscription-limit exhaustion is a distinct failure class, not a transient error**: Claude Code currently does *not* auto-fallback from OAuth to an API key on limit-exhaustion (open feature request, issue #43260) and doesn't expose %-utilization headlessly (issue #78476, closed as won't-fix) — so your orchestrator must (a) pattern-match the known error strings ("You've hit your session/weekly/Opus/Sonnet limit") or the `rate_limit_info.status`/`rateLimitType` fields from `rate_limit_event`, (b) treat a hit as "stop routing to this identity for the remainder of the window," never as "retry the same account," and (c) ideally pre-empt this reactively-discovered wall by polling `ccusage` output or Codex's `/status`/session-file `used_percent` *before* dispatching a large job, degrading proactively to OpenRouter/local when either window is within ~10–15% of its cap.

General notes: "rough cost" for anything routed through the Claude Max or ChatGPT Pro subscriptions is $0 marginal as long as you're inside your 5-hour/weekly quota — the real spend only appears when you overflow to metered OpenRouter/API calls, so the policy above is really a *quota-preservation* ordering (cheap/local first, subscription-backed frontier for anything genuinely hard, metered pay-per-token only as the last-resort circuit-breaker path). Your local MLX models and the RTX 5090 box double as a zero-cost, zero-ToS-risk tier for the high-volume/low-stakes classes (triage, mechanical fixes, first-pass review) and as an offline fallback of last resort if Claude, OpenAI, and OpenRouter are all simultaneously unavailable or exhausted.
